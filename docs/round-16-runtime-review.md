## 测试兼容风险清单

- 存档读取先创建当前Game再按全部脚本变量检查shape。新增必填经济字段若不在旧版迁移阶段补齐，会把所有真实旧fixture拒绝；若总版本升7，现有`[1,2,3,4,5,VERSION]`必须显式保留6。
- `tests/round15_pool_test.gd`对真实v5采用“只改外层版本后整份snapshot相等”的断言。新增合法迁移字段后需明确检查这些中性默认字段，并继续逐项保护原字段、metadata和两个RNG；不能为让测试通过而覆盖旧原始值。
- 神仙/租金、建筑、商店、乐透、现金格、清偿/股票、队伍等测试含精确金额。中性物价1应继续保持已有断言；高物价用新案例覆盖报价、实际付款、折扣/取整、清偿和资产结算，不能把旧测试统一改成随实现自行计算而失去独立预期。
- 四种小游戏的现有测试明确比较`cash_before + record.reward`，并验证取消未领奖结果不泄漏奖励。若将现金奖励与分数分离，必须同时更新schema、严格validator、所有结束路径和旧存档迁移，保留取消与一次领奖测试。
- 多个旧测试直接设置round_number构造开奖/神仙周期。未来若增加独立经济时钟，需区分合法推进与刻意构造状态；存档验证不能接受相互矛盾的时钟，也不应无说明地重算旧局日期。
- 自然AI与UI完整比赛会因资金变化改变买地/破产/路线和RNG调用轨迹；抽样未碰到某玩法属于覆盖变化，需要补确定性种子，不能掩盖真正的卡住或将自然比赛改成强行设置phase。
