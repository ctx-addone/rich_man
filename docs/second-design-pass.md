# 第二轮游戏设计与优化：讨论基线

日期：2026-11-08。用户要求先推送当前版本，再进入第二轮设计与优化。本文件是下一阶段的讨论与验收提纲，不代表新增功能已实现。此前R1—R15是内部实施批次，与用户本次所说的“第二轮设计”分别计数。

## 当前可试玩基线

游戏代码基线为 `5da636a8ed5f7896abcabe4fc4562694c05aba04`，版本v0.15。Godot 2D、单机热座及基础电脑、菜单到终局流程已经具备；道路与独立建筑、多入口产权、医院监狱、银行股票、卡牌神仙、队伍、骑士庄园、新闻子集及四种小游戏已有实现。当前仍有大量测试参数，完整原作玩法尚未还原。

上一批次留下44组模型回归、三个小游戏实际界面测试和两场完整热座界面对局证据，见 `docs/round-15-report.md`。它们证明已实现规则下的运行结果，不证明全部规则与原作一致。本次冻结准备材料不修改游戏代码，也不把已有测试记为本次重新执行。

## 建议的设计顺序

| 优先级 | 设计议题 | 需要回答的问题 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 操作可理解性 | 玩家是否知道现在轮到谁、能做什么、操作会花多少钱、结束后会发生什么？ | 从主菜单开始记录第一次试玩中的停顿点；购地、分岔、反制、银行、小游戏均有明确下一步和结果反馈 |
| P0 | 整局节奏 | 一局有多少有效决策与重复确认？电脑行动、热座交接、小游戏是否过度打断棋盘？ | 固定地图与种子记录总时长、手动操作次数、等待时长、破产与终局时点；对改动前后进行同条件对比 |
| P1 | 经济与策略 | 初始资源、物价、地价、租金、升级和奖励如何影响购地与现金储备？ | 各收支类别独立核验；报价、实际扣款、资产显示、读档结果一致；不把所有现金变动统一乘物价 |
| P1 | 地图可读性 | 道路、建筑入口、产权、等级、特殊设施和角色状态是否一眼可分？ | 在正常缩放下检查路线选择、同楼多入口和医院监狱出入口；沿用原创占位素材，先验证信息层级 |
| P2 | 内容完整性 | 当前原作差距中，哪些直接影响整局策略和胜负？ | 继续按既有完整目标清单逐项追踪NPC、地图机关、热斗和挑战；不因本轮优化缩小目标范围 |

以上为推荐顺序，具体优先项可随用户试玩反馈调整。优化首先服务既有玩法表达与规则还原，新增原创机制另行讨论。

## 下一次实施的交付要求

每个优化项写明问题、规则或交互变化、影响范围与验收场景。未找到原作依据的数值继续标为测试配置；模型测试和实际操作验证分别记录。存档升级要保留旧局的资金、产权、随机状态和未结算事务。完成一组改动后更新分类策划与对照结果，再提交可试玩检查点。
