# R15 投娃娃：规则证据与独立模型

核对日期：2026-11-08。投娃娃作为新的小游戏类型接入骑士庄园，使用独立模型 `scripts/model/toss_dolls_rules.gd`；不修改接金币 `catch_coins/version=1` 的字段、参数或随机数顺序。当前实现是已证操作机制加明确测试参数，不称为原作完整小游戏系统。

## 原作支持到哪里

本轮直接查看了 KillKill龍 2024-05-02 骑士庄园困难领主雪莉实机的201.5秒说明页。文字要求按娃娃性别分别投左右两边，炸弹直接扔掉、不要留在手里或扔进篮；PC操作为点击投掷位置。画面左蓝篮、中间垃圾桶、右粉篮，顶部有当前物品与后续预览。[说明画面定位](https://www.bilibili.com/video/BV1hw4m1C7Tm/?t=201)

研究员补核了末尾连续片段：219秒剩一只女娃时9800分，220秒投粉篮后10150分，清晰增加350；之后队列为空，时间条尚约27%且停止，随后结束。支持“单娃350分”的本样本推断，以及“处理完有限队列可提前结束”的直接行为；不能从29个成功娃娃推导原作总物品数。[末尾片段定位](https://www.bilibili.com/video/BV1hw4m1C7Tm/?t=219)

2022-10-14首发宣传稿描述炸弹误入某一侧篮子后，该篮娃娃清空并结束。这是宣传文字证据，本轮实机没有故意命中炸弹，不能进一步推断眩晕、两篮同时清空或所有积分归零。[宣传稿转载](https://www-ali.gamer.dog/news/html/2022-10/713119.html)

同一实机开局四席均为“我”，一次小游戏只有触发席手动玩，其他本地人类席与领主自动显示分数，最后五席都增加现金。投娃娃与接金币均已核到这个流程。因此本版仅触发席手操，其余参与席内部自动按同规则处理物品，不要求其他热座玩家各玩一遍。[开局配置](https://www.bilibili.com/video/BV1hw4m1C7Tm/?t=30)、[全席结果](https://www.bilibili.com/video/BV1hw4m1C7Tm/?t=225)

研究缓存 `docs/research/evidence/r15-dolls-201.5.png` 及后续帧不入Git、不作为游戏素材。完整前后余额、当前角色糖糖和路德维希身份纠错见 `docs/research/r14-news-minigames.md`。物价2的样本中触发席现金=分数×2，其他席现金=显示分数×2/3；当前模块仍按每席自身得分等额发奖，是明确测试差距，不宣称复刻了这些自动分数与倍率算法。

| 项目 | 当前实现 | 依据或边界 |
| --- | --- | --- |
| 三个容器 | bin_id 0=左蓝篮，1=垃圾桶，2=右粉篮 | 说明页直接可见 |

| 错色/丢弃娃娃 | 消耗该物品，不入篮、不加分，继续 | TEST-R15；原作错色具体惩罚未知 |
| 炸弹误入篮 | 只清命中篮，保留另一篮并立即结束该席 | 宣传稿P；不把未演示的额外惩罚当事实 |
| 未处理炸弹 | 到下个tick时结束，保留已入篮娃娃 | “不要留手上”已证；一tick期限、保留分数为TEST |

| 输入与动画 | 点击锁定一次投掷，到下个0.5秒tick结算；同物品不允许重复点击或换篮 | TEST离散动画近似；原作即时点击/移动动画精确耗时未知 |

| 预览/补充 | 可见队列最多4件，含当前头物；处理后依次前移，只补至总供给40件；尾段自然缩短 | 队列预览与有限结束已证；预览数、总量及三类等概率为TEST |
| 提前结束 | 最后一件处理完立即queue_empty，不等待计时结束 | 连续实机直接支持 |

小游戏不会直接随机发现金。物品类型随机，但分数来自实际投掷历史与两个篮子的状态。AI只读取当前公开头物，使用与人相同的toss/tick指令；既不读取未展示随机结果，也不直接写分数。其他本地人类席自动参与时采用这个确定性策略，不声称是原作自动分数分布。

## 模型与存档契约

外层仍为 `pending_service={kind:'minigame',road:int,game:Dictionary}`。投娃娃的 `game.id='toss_dolls'`、`version=1`。所有状态都是普通字典/数组；使用对局g.rng，无模块实例随机状态。核心字段如下：

| 字段 | 内容 |
| --- | --- |
| player、participants、cursor | 固定未破产参与名单与当前内部模拟席；棋盘g.current一直是触发人 |
| tick、status、reason | 当前席已过tick；ready/playing/participant_result/result；空原因或bomb_blue/bomb_pink/held_bomb/queue_empty/time_up |
| queue、spawned | 当前最多4件公开预览，条目为blue/pink/bomb；本席已生成物品数，最多40 |
| choice | -1尚未投掷，0/1/2为当前头物已锁定的容器 |
| baskets | `{blue:int,pink:int}`，记录当前仍在两篮的娃娃数 |
| events | 按严格递增tick记录 `{tick:int,kind:String,bin:int}`；普通娃无操作的tick不记处理事件 |
| score、reward | score由两篮重算；reward只在本席结束后确定，全部完成前不入现金 |
| history | 已完成席记录 `{player,tick,events,baskets,score,reward,reason}`，用于统一派奖与严格重放校验 |

`enter/start/tick/next_player/settle_others/ai_step/close/state_error` 与公共分流器对接；专用输入是 `toss(g,bin_id)`，只读建议是 `ai_bin(g)`。模块提供 `TITLE/INSTRUCTIONS/PARAMETERS/TEST_PROFILE` 给UI。跨游戏调用投娃娃方法返回false，不能对接金币误读字段。

`state_error(state,g)` 重放事件恢复两个篮子、分数与结束原因；检查事件时刻、总供给、队列数量、预览种类、选择范围、参与名单/顺序、完整历史与每个收款人，拒绝伪造分值、提前领奖、结束后追加事件及错误schema。历史分值由真实记录推导，上限40×350=14000；炸弹清篮后只能按剩余篮结算。

本轮总存档为v6；真实v5接金币继续走原版本校验与运行逻辑，恢复时不得重新抽小游戏。投娃娃状态不能伪装成v5。准备页、已选但未结算的投掷、缩短的末尾队列、提前爆炸、队列空、超时、内部其他席模拟和最终未领奖结果都可保存。

## 验证结果

`tests/toss_dolls_test.gd`：`TOSS_DOLLS_TEST failures=0`。覆盖真实地图入口、明确GM选型、准备等待、合法/非法容器、快速重复点击拒绝、预览真实性、已选投掷保存复现、正确娃+350、错色/丢弃测试策略、左右篮分别被炸后只清对应篮、持弹结束、未投普通娃保持与超时、有限40件提前结束、所有参与者独立分数及一次统一领奖。

自动批量模拟与逐条人工等价指令的完整快照一致；篡改分数、篮子、队列、时钟、总供给、事件、结束原因、参与名单或收款人均被拒绝；GM中断不发未领现金。另以种子1400、35轮自然跑完骑士庄园FFA和2v2两局；在四种抽选池下，以1510..1515作有限补充覆盖，实际由1512自然进入投娃娃并完成整局。测试不假定抽选池只有两种，也不以强制设置小游戏阶段代替自然覆盖。原作尚未核定的错误颜色、炸弹精确倒计时、生成分布、物价/自动奖励公式集中保留为测试规则。
