# 大富翁11：地产、经济、特殊设施与胜负证据

研究日期：2026-11-08。对象：Steam PC 国际版《大富翁11》；首发资料与后续社区资料分开标注。**本文是规则研究，不是已实现清单。** 未取得当前安装版本的完整游戏内数值表，因此不能宣称数值级还原。

## 证据等级与版本

- A：开发商/发行商官方说明，确认机制存在与官方描述，不自动证明未展示的公式。
- B：明确标为11代的同期图文攻略；可作为实现候选，关键数值仍应与游戏内说明交叉验证。
- C：明确区分代际的社区资料或玩家记录；保留版本、模式限制，等待原游戏验证。
- U：未证实。不得用4/4Fun/8/10、经典 Monopoly 或原型自定值填入“原版规则”。

大陆发行版存在名称和表现调整，不能将“休息室/学习中心”等名称差异误判为国际版没有医院/监狱。版本差异线索见 [11代社区条目](https://richman.fandom.com/zh/wiki/大富翁11?variant=zh-sg)；本项目以国际版为基准。2022资料不是2026版本完整目录，后续内容还需更新记录验证。

研究中发现的污染源：[九游怀旧文章](https://www.9game.cn/news/8790193.html)前半段讲旧作董事长和保险，末尾转谈11；不能据网页包含“大富翁11”就将前半段当成11规则。[所谓手游移植/下载攻略](https://www.danji100.com/game/130512.html)混入经典 Monopoly 抵押、双骰出狱与固定保释费，不作为本项目证据。

银行不能只做“停在此处领钱”的事件。应设计现金与存款独立账户、经过服务交互、月结事件及拒绝服务状态；利率等未核实参数必须有 `provisional` 标记。股票交易/估值记录应与地产账本分开，以便之后替换真实清偿顺序。

## 六、优先补证与验收用例

以下为本项目建议，不是原版事实：

1. 同一地产：分别经过、最终停留、被传送到达；记录收租/购买/升级窗口。多临路节点重复触发测试。
2. 小地产：逐级截图记录建造费用和租金；同街增减产权、切换连锁店、队伍代建，比较差值。
3. 大建筑：每级各执行一次主动与被动作用；酒店记录完整度假生命周期；转盘保留样本不以少量样本推断概率。
4. 银行：经过但不停留、停留、拒绝服务、跨月；依次制造现金不足/存款不足/持股/有地产等清偿案例。
5. 医院/监狱：用不同来源进入，核对状态期间收租、用卡和股票；记录释放后位置与方向。
6. 胜负：单人队、多人队、队友先破产、时间结束、资产相同、挑战领主破产分别记录。
7. 股票/保险：仅以实际菜单、教程、官方补丁或实机录制确认；不要从旧作攻略填空。

研究参考图片只用于证据；不放入游戏 `assets`。本文件配套 `r11-economy-specials.facts.json` 保留明确规则、证据等级、待核验参数，便于策划/代码引用。资料的存在不意味着对应功能已经完成。
