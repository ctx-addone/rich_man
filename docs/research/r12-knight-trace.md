## 编号、坐标及来源

节点 ID 使用 `n_aa_bb`；负数 b 用 `m`，例如 `n_00_m02` 是 `(0,-2)`。逻辑坐标 a 沿小地图右下，b 沿左下。它们是描图坐标，不是原作内部节点 ID，也不规定玩家移动方向。

K2 仿射候选：`pixel = (590,201) + a*(26,20) + b*(-31,17)`。K1 对照候选：`pixel = (402,89) + a*(24.15,18.71) + b*(-28.82,15.73)`。`screen_estimates` 是对齐后的估计中心，非逐点鼠标量测。截出画幅的坐标仍保留估计值，以实机补图为依据，不声称该像素可在原截图直接看到。

## 地产与功能候选

58 个独立圆角小地产分别对应一个可见临路格。4 个大地产候选 `p_059..p_062` 分别临：

| 大地产候选 | 两个可见临路格 |
|---|---|
| 北侧 | `(7,0)`、`(8,0)` |
| 中央 | `(12,7)`、`(12,8)` |
| 底侧 | `(19,14)`、`(19,15)` |
| 东侧 | `(20,0)`、`(20,1)` |

这些是**路旁同一大地块的几何关系**。不能据此断言落到两个格都购买/收租，也不能拆成两个独立产权；数据明确保留 `entrance_rule: U`。小地产的精确名称、价格、街道连锁分组仍未复原。

四角方形标记只是道路纹理，不能统一当作无地产空格。K5 01:30 玩家在该纹理格弹出“老城区、空地、2400 元”购地框。本轮数据以 `visual` 与 `property_ref` 分开记录。

紫星、红叹号、青色门店、蓝数字球、手柄等保留功能候选。黄色猪形和蓝色矩形图标仍记为 `unresolved_service`，待设施专项来源确认，不能因颜色或形状直接新增规则。带数值的现金格使用截图印字；数值不包含物价计算推断。

## 哪些边或规则仍是 U

本次描图的 **104 条静态相邻边均有 B 级可视证据候选**，不存在为了凑数添加的匿名边。`geometry_confidence` 与通行规则分开：

- 医院边 `(0,8)—(1,8)`、监狱边 `(0,-2)—(0,-1)` 的格子几何可见，但平时能否主动进入、受罚送入后的离开方向仍为 `U_facility_entry_release`。
- 其余边的正反通行、三岔是否允许自由选择、经过服务是否打断移动均未用连续操作验证，记为 `U_direction_selection_not_verified`。无向图只表示几何相邻。
- 大地产的两格触发关系 U 不影响已有道路编号，但会影响后续可玩实现。

## 独立审核与纠错记录

初稿把部分地图的视觉直线当作道路延伸，及把乐透当作外伸死端；放大 K1、对比 K5 后发现那些“直线”上实际是圆角地产。双方复核改为三处 Z 折。初稿还曾将四角纹理误记为空格、将底角后的一个购地格与纹理格重复计数；购地弹窗与逐格对齐已纠正。本文件和 trace JSON 优先于 R11 的这些局部顺序描述。

独立审核者按路段重数同样得到 102 节点、104 边、6 个三岔和 2 端点。另一份审核记录由地图审核任务单独提交，保留上述被撤回的假设及其纠正理由。

本地完整性检查通过：节点/边唯一、所有边端点存在、所有 104 条边与 102 个节点的来源引用合法、邻接双向对称、全图连通、地产引用一致且同一路格不重属两个地块。此检查证明研究数据自洽，不代替游戏规则验证。
