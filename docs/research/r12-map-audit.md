# R12 骑士庄园道路与功能标记独立复核

复核日期：2026-11-08。本文件只记录独立图审与可交付的边/节点纠错，不修改核心或追踪JSON。目标为已有截图及PC视频中的《大富翁11》骑士庄园；不把静态图审等同于完整规则实机验证。

## 图源与方法

- **K1**：`evidence/knight-full.jpg`，1029×705，游民原作者Shy夏夏的骑士庄园全图。底角及最上设施边缘有裁切。[原攻略](https://www.gamersky.com/handbook/202210/1526713_7.shtml)
- **K2**：`evidence/r11-facilities/wide-map-example.jpg`，1726×970，实玩文章小地图，底部与右侧受窗口遮挡。[作者文章](https://game.3loumao.org/153167078) · [原图](https://imgheybox.max-c.com/web/bbs/2022/11/21/189e6597a2de007e8887761a642843ed/thumb.jpeg)
- **HD**：`evidence/knight-p8-hd-105.png`、`-110.png`、`-150.png`、`-200.png`，底角及下边街景；追加 `-90.png`、`-130.png`、`-135.png` 验证可购地格、医院及监狱区域。这些是同一PC录像第8P对应秒数的公开画面缓存，原视频记录由地图追踪文档维护；不把抽帧当作亲自操作原作。
- **对照标注**：`evidence/knight-grid-review.png` 是研究线程的K1格网标注。我使用同一坐标命名独立核对实际格边界，不把标注点自动视为已确认道路。

坐标约定：以K2上方斑马线约(591,201)为逻辑 `(a,b)=(0,0)`，a轴向右下，b轴向左下；近似屏幕步长分别为(25.8,20.2)与(-31,17.3)。这只是图审坐标原点，**不是游戏起点**。K1、K2投影比例不同，像素位置只用于查找原画，最终以路格边框、相邻地产和高清街景交叉判断。

### 已发送给追踪线程的具体纠错

1. **底角不能跨过斑马线。** HD105/110/150/200共同确认 `(17,17)+5000 → (18,17)紫星 → (19,17)斑马线转角 → (19,16)红!`。K1底角裁切不能变成紫星直接连红!。西南两个外角之间有8条边，不是7条。
2. **下边乐透是主路错位，不是死端支线。** 正确为 `(19,13)→(19,12)→(20,12)乐透→(20,11)→(20,10)…`；`(19,11)/(19,10)` 是路旁圆角地产，不是沿直线延续的道路。
3. **中右乐透也有同样错位。** `(12,3)→(13,3)乐透→(13,4)→(13,5)→(13,6)→(13,7)`；不能用 `(12,4..6)` 的地产块顶替道路。
4. **真正的中部三岔在斑马线上。** `(13,7)` 连接 `(13,6)`、`(12,7)`、`(14,7)手柄`。`(12,7)` 是转折节点，向西北是大型地产，不能多连一条路或把它画为四岔。
5. **右侧银行再错开一格。** 外围从 `(20,-2)` 沿b轴到 `(20,2)`，再到 `(21,2)蓝单卡`，随后沿a=21行走；不能把a=21的上段空白或a=20下段地产误补为道路。
6. **下侧商店是真三岔。** `(20,7)` 连 `(19,7)`、`(21,7)+2000`、`(20,8)`；地图标记圆形盖住格面不能导致漏边。
7. **四角方框只是格面纹理。** HD90玩家停在四角纹理格，界面显示“老城区”、空地2,400；HD130/135还显示转角纹理旁有独立地契。此类节点可能有地产，不能统一归为“空白功能格”，也不能仅凭纹理判成三岔。

最初粗看时，我曾把两个乐透误判为一格死端，并已在与追踪线程的消息中明确撤回。上面的错位道路结论来自放大K1格边界并与HD90/150交叉检查，是本审计的最终结论，不保留错误支线假说。

“加钱与减钱格独立存在”另有Steam玩家第一手实玩描述支持，而非只靠图标联想。该作者明确描述多处此类地格；文字不足以证明逐步经过也结算。[2024-10-31玩家评测](https://steamcommunity.com/profiles/76561198826143376/reviews/)

HD105/110显示物价1，HD150显示物价2，HD200显示物价3；这几帧的同一底边格面仍印着+5000，附近仍可见+2000。因而应分别记录 `visible_amount` 和实际结算公式，不能把印字自动视为最终入账值。这里不反向断言“金钱格不受物价影响”；缺少无其它收入/支出的连续余额验证。

## 新闻与小游戏：本轮新增可用证据

官方国际Steam说明明确传统地图含新闻，且不同功能地图格由道路连接。它支持把新闻和地产/银行等分开建模，但没有给出红!图例或完整事件表。[官方介绍](https://store.steampowered.com/app/2074800/_11/?l=schinese)

**新闻的实际候选条目：释放在押者。** 触乐祝思齐在2022-10-22的Steam实玩记录中描述，刚把对手送进监狱，随后踩新闻事件使所有人被释放。这是11代PC第一手体验，可加入候选新闻证据表；仍不能把“所有人”泛化为清除冬眠、梦游、度假等全部状态，也没有证明抽取概率。[触乐原文](https://www.chuapp.com/article/288938.html)

**小游戏的实际类型：接金币。** 3DM原作者评测明确游玩了接金币小游戏，并描述通过鼠标点格移动。它证明独立操作环节，不能用一个随机奖金弹窗代替后声称已还原。该文提到生日/ATM给2,000的句子是行文中的对比例子，未当作逐条核验的原作新闻目录使用。[3DM原评测](https://www.3dmgame.com/score/3742848.html)

玩家讨论还提到问号、感叹号两类随机事件标记；这可以提示后续分别核对图例，但本轮没有读清两个黄色图形的内部符号，因此不直接建立“黄色＝问号＝命运”的连等关系。[11攻略作者讨论](https://youhua.baidu.com/p/8995417048?pn=2)（检索索引可读，原页访问受限）

“命运”一词也出现在玩家反复停留魔法屋的统计描述中。没有菜单标题和格面同帧时，它可能只是玩家对随机结果的称呼；不能因此添加一个不存在证据的独立命运屋。已知魔法屋仍按先选效果、后抽条件的11代顺序研究。

## 对录图与运行时入口的直接约束

1. 102节点应按上述实际路格构成；医院/监狱端部路格、被裁底角及Z折格都应独立编号。圆角地产不能计入道路。
2. 先分离“初始化站位”“逻辑坐标原点”“正负现金道路事件”。本图未看到START或共同起点奖励标记；这足以否定把任意+2000格解释成唯一绕圈起点奖励，但不足以证明所有角色初始站位的完整规则。
3. 保存格面文字及图源版本，事件触发时机、物价倍率和资格另行标证据。现金格、新闻格、小游戏格应有不同来源，不继续统一冒充随机+500机会事件。
4. 四角纹理/斑马纹理属于道路显示；地产入口与路口度数另由实际产权和边界确定。
5. 本审计提供拓扑纠错，不把未识别图标的功能、初始化spawn、医院/监狱释放计步或整张原作地图数据完整性一并宣称完成。
