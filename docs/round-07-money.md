# 第七轮：待支付事件与金损防御

本轮把租金、商业中心随机倍租、酒店租金与查账从立即扣款改为待支付事件。当前行动者不改变，付款者先选择防御；确认后才进入既有清偿流程。主动购地、升级、改建、买卡、股票交易不经过此窗口。财神/穷神入场转账、均贫/均富仍不归入本轮金损事件，未宣称覆盖所有金损来源。

免费卡只在合格金损反应中使用，取消本次付款，不取消酒店住宿。转移改变付款者，收款者与金额保留；接收者可继续免费或转移，访问集合防止循环。当前转移目标沿用健康、存活、未访问玩家，允许收款者，转移给收款者视为自己债权抵销且不卖资产。睡眠及其他受限状态不能使用被动防御。

免费消费先释放手牌空间，然后触发十一获得遥控骰子。内部奖励窗口仅包围反应消费后的天赋调用；外部GM发牌、股票交易等仍不能在reaction期间修改状态。新队列与既有住院/监狱/同命反应共用接口。

## API与时序

`Money.begin(game,payer,amount,receiver,source)` 创建pending_attack事件，kind=money，amount/receiver为金额/收款人。只入队；调用者按现有规则执行Combat.advance。`reaction_description/options/targets/resolve_reaction`保持接口，UI使用同一交接窗口。

落地维护landing_queue，收费前移除已处理地块。反应结束从剩余地块继续，商业中心倍率不重抽、已收租不重收、机会事件只执行一次。hotel后果保留在landing_hotel；免费或转移后实际到访者仍住店。破产/终局清理待落地流程。

## 证据与测试参数

首发卡表确认免费/转移支持达到一定金额的损失；11代查账可被防御。传统模式酒店免费卡旁证及饭店费用防御后仍住宿的规则见本轮研究。原版阈值及比较符未核实，Money.TEST_PROFILE.reaction_threshold=500、采用大于等于均为测试配置。转移多次、目标资格、自己债权抵销、扣款清偿次序并非已核实原版细节。

查账仍以目标现金15%为暂定税额，免费免该款；转移后第三者的清偿仍使用统一临时模型（现金、存款、股票、地产），不是原版已确认。酒店住店持续和商城倍率同样保留既有测试参数。

## 验证

money_test覆盖阈值上下、免费/十一奖励、外部mutation阻止、转移收款人保留、防循环、接收者免费、睡眠禁用、真实地块落地暂停/继续、酒店费用免除后仍住宿、破产和查账。core_test 50局仍通过。主任务负责完整UI与全套回归。
