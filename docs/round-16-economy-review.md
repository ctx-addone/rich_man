# R16 独立经济回归与审查

日期：2026-11-08。独立经济回归已执行，最终全部通过。独立审查只新增本文件与 `tests/round16_economy_test.gd`，未修改核心、界面或存档实现；发现的核心问题由主集成修复。

## 待验收合同

`Game.setup` 的 `economy` 选项包含整数 `initial_cash`、`initial_deposit`、`inflation_interval`；兼容默认10000、0、0，现金/存款合法范围0～500000，周期0～365。运行时使用 `Game.economy_config` 和 `Game.price_index()`。有限期测试日暂以 `min(round_number, round_limit)` 表示，开启时物价为 `1 + floor((day - 1) / interval)`，周期0关闭，终局不多涨一次。本轮追加 `round_limit=0` 无限期，此时按实际round_number计价，不封顶；负rounds参数保留旧行为钳为1。

不传经济设置时采用 `policy="legacy_v6"`；显式传入但省略policy时采用 `r16_samples`。非法类型、未知字段或策略应在修改对局之前拒绝。新策略的新闻/小游戏服务增加 `pricing={day,price,other_divisor:3}` 冻结本次计价；旧策略不增加该服务字段。小游戏内部 `record.reward` 保留原始分数，`Minigame.cash_reward(g, record)` 给出实际现金：触发者为分数×物价，后台席为 `floor(分数×物价/3)`。既有研究中将后台比例写成“物价×2/3”属于误解，物价2下观测到的是分数×2/3，不能再额外乘2。

本批次对租金、房屋补贴和小游戏最终奖励接入物价，小游戏区分触发席与后台席。购地、加盖、商店卡价不改变；其他未核定收支不借用通用倍率。范围和公式是项目本轮合同，不声称等同原作全部经济系统。

## 独立发现的问题与修复

首跑出现4个实际金额断言失败，全部来自拆炸弹：`close` 原先先清除 `pending_service`，随后才调用新计价函数。计价函数读取不到冻结的pricing，回退旧1:1奖励；因此新策略下预览与实发不符，触发席少付、后台席多付。该问题不影响其他三种小游戏，它们在清服务前计算了金额。

已向主集成反馈；主集成将拆炸弹改为清服务前计算全部payouts、清服务后实际发钱，继续保留清状态后做副作用的顺序。本独立测试仍按公开 `close` 核对四席现金，没有降低预期或绕过领奖入口。

算术安全追加验证：setup拒绝期限1000000001和int64最大值，原局与RNG不变；Save拒绝超过1000000001的round_number、超过1000000000的有限期限及两类int64极值。`MAX_DAYS=1000000000`是序列化/金额算术的防溢出边界，不是无限期游戏自动结束的天数，也不是原作日历上限。

四种小游戏逐步比对原局/读档后的完整状态与两套RNG，最终基础分保留，分席实际现金正确且只领取一次。另测触发席为2、周期关闭但显式采用新策略的场景，后台席仍按除3政策结算；这与旧档的所有席1:1清楚区分。
